- 支持 Windows 10（1809 / 21H2 / 22H2）与 Windows 11，x64 与 x86 均可
- 支持 100% / 125% / 150% / 175% / 200% 缩放与多显示器

## 一、快速开始

1. 把 `HomeworkBoard.exe` 放到任意可写目录（**推荐桌面或 D 盘新建一个文件夹**，不要放 `C:\Program Files`）。
2. 双击运行。首次启动会自动生成两个配置文件。
3. 启动后窗口出现在**主屏右侧**，距屏幕边缘 20px。

**基本操作**

| 操作 | 鼠标 | 触摸屏 |
|---|---|---|
| 移动窗口 | 按住标题栏空白处拖动 | **手指按住标题栏空白处拖动** |
| 添加作业 | 点科目卡片标题右侧的 `＋` | 轻触 `＋` |
| 编辑作业 | 点条目右侧的 `✎` | 轻触 `✎` |
| 删除作业 | 点条目右侧的 `✕`（会二次确认） | 轻触 `✕`（会二次确认） |
| 标记完成 | 点条目方框，或点文字 | 轻触方框或文字（**命中区已放大**） |
| 上下滚动 | 滚轮 / 拖动滚动条 | **手指上下滑动（带惯性）** |
| 切换置顶 | 点标题栏 `📌`（亮蓝色 = 已置顶） | 轻触 `📌` |
| 打开设置 | 点标题栏 `⚙` | 轻触 `⚙` |
| 最小化 / 关闭 | 点 `─` / `✕` | 轻触 `─` / `✕` |

> **触摸屏说明**：程序已针对教室触屏一体机做过专门适配——
> 所有按钮放大到 34–42px 命中区、滑动条拇指加粗到 26px、
> 标题栏支持手指拖拽（带 8px 抖动过滤，不会误触）、内容区支持手指惯性滚动。
> 手指拖动窗口时请按在**标题栏的空白处**（日期文字那一行），不要按在按钮上。

**工具条按钮**

| 按钮 | 作用 |
|---|---|
| `↻` | 重新载入 JSON（用记事本改完配置后点它立刻生效，无需重启） |
| `💾` | 立即写盘（平时会自动保存，这个用于确认） |
| `📂` | 打开程序所在文件夹并选中 `settings.json` |

## 一点五、怎么加作业（详细步骤）

### 方式 A：在界面上加（推荐日常使用）

启动后窗口里会列出**所有启用的科目**，每个科目一张卡片：

```
┌─ 语文  3 项 ──────────── ＋ ┐
│  ☐ 练习册第 12 页 1-8 题  ✎ ✕ │
│  ☑ 背诵《静夜思》         ✎ ✕ │
└──────────────────────────────┘
┌─ 数学  1 项 ──────────── ＋ ┐     ← 有作业：正常配色
│  ☐ 书第 45 页            ✎ ✕ │
└──────────────────────────────┘
┌─ 英语  暂无作业 · 点右侧 ＋ 添加 ┐  ← 无作业：淡化显示
└──────────────────────────────────┘
```

1. 点对应科目卡片标题右侧的 **`＋`**，弹出编辑框。
2. 点一个**模板胶囊**，例如「练习册」：
   - 输入框自动填入 `练习册第  页`
   - 光标停在两个空格中间
3. 直接敲键盘输入数字 → `练习册第 12 页`
4. 按 **回车** 确认（或点「确定」按钮）。

**一科要加多条作业**：重复第 1 步即可，点一次加一条。

**不想用模板**：第 2 步跳过，直接在输入框里手打完整内容。

**模板可以组合**：先点「练习册」再点「背诵」，会拼接成
`练习册第  页；背诵：`，再补数字即可，适合一次布置多种作业。

> **关于「空科目也显示卡片」**
> 原始需求写的是"没有作业的学科不显示对应窗口"，但实际使用中发现两个问题：
> ① 全部科目都没作业时界面空白，找不到添加作业的入口；
> ② 科目位置随作业增删而变动，教室大屏上学生难以形成固定认知。
> 因此经确认改为：**空科目也常驻显示，但视觉上淡化**——
> 色条转暗灰、标题转灰、不显示"0 项"角标、卡片背景更暗，并提示"暂无作业 · 点右侧 ＋ 添加"。
> 好处是科目位置永久固定，`＋` 永远在同一位置可点。
>
> 如果你确实想让某些科目完全不显示，把 `settings.json` 里该科目的 `enabled` 改成 `false`。

### 方式 B：改 JSON 批量录入（开学/期末批量导入更快）

1. 点悬浮窗工具条上的 `📂` 打开程序文件夹（会自动选中 `settings.json`）。
2. 用**记事本**打开 `homework.json`。
3. 找到 `"dates": {` 这一行，在里面加今天的作业。格式如下：

```json
"dates": {
  "2026-09-18": {
    "chinese": [
      { "id": "", "content": "练习册第 12 页 1-8 题", "done": false, "createdAt": "" },
      { "id": "", "content": "背诵《静夜思》", "done": false, "createdAt": "" }
    ],
    "math": [
      { "id": "", "content": "书第 45 页", "done": false, "createdAt": "" }
    ]
  }
}
```

**注意 5 点**：

| 要点 | 说明 |
|---|---|
| 日期格式 | 必须是 `yyyy-MM-dd`，**月日要补零**（`2026-09-08` 不是 `2026-9-8`） |
| 科目键名 | `chinese`/`math`/`english` 等，必须与 `settings.json` 里的 `key` 一致 |
| `id` | **留空字符串即可**，程序会自动补一个唯一值 |
| 逗号 | 多个作业之间用**英文半角逗号**分隔；最后一条后面**不能有逗号** |
| 引号 | 全部用**英文半角引号** `"`，不能用中文引号 `“”` |

4. 保存文件（Ctrl+S）。
5. 回到悬浮窗，点工具条的 **`↻`** 重新载入 → 作业立刻出现。

**如果嫌一天一天写麻烦**：可以先按上面格式准备好一个星期的，用记事本另存为一次即可，程序只显示当天的部分。

## 三、JSON 字段说明

> 两个文件都是 **UTF-8 纯文本**，可以直接用记事本打开编辑。
> 所有以 `_` 开头的字段（如 `_说明`）都是写给人看的注释，**程序读取时会完全忽略**，你可以随意修改甚至删掉。

### 3.1 settings.json

```json
{
  "version": 1,
  "_说明": "以 _ 开头的字段是说明文字，程序会忽略。改完保存后点悬浮窗上的 ↻ 即可生效。",
  "window": {
    "opacityPercent": 92,
    "topmost": true,
    "fontSize": 20,
    "titleFontSize": 22,
    "columnWidth": 320,
    "maxHeight": 720,
    "edgeMargin": 20
  },
  "subjects": [
    { "key": "chinese", "name": "语文", "color": "#FF6B81", "enabled": true, "order": 10 },
    { "key": "math",    "name": "数学", "color": "#4A9EFF", "enabled": true, "order": 20 }
  ],
  "templates": [
    { "label": "练习册", "prefix": "练习册第 ", "suffix": " 页", "enabled": true }
  ]
}
```

#### window 对象

| 字段 | 类型 | 取值范围 | 含义 |
|---|---|---|---|
| `opacityPercent` | 整数 | **70–95** | 窗口透明度百分比。超出范围会被自动夹到边界值 |
| `topmost` | 布尔 | `true`/`false` | 是否窗口置顶。**会被保存** |
| `fontSize` | 整数 | 12–48 | 作业条目文字大小（像素），教室大屏建议 22–30 |
| `titleFontSize` | 整数 | 12–56 | 科目名称字号（像素） |
| `columnWidth` | 整数 | 200–800 | 卡片宽度（像素）。调小可以在同一行放下更多科目 |
| `maxHeight` | 整数 | 300–1400 | 窗口最大高度（像素）。超出后内容区上下滚动。程序还会自动与屏幕工作区高度取小值，保证窗口不会压到任务栏。默认 720 |
| `edgeMargin` | 整数 | 0–200 | 窗口距屏幕边缘的距离（像素），默认 20 |
| `manualWidth` | 整数 | 280–1600（**0 = 未设置**） | 上次手动拖拽调整后的窗口宽度。`0` 表示从未调整过，此时使用默认 380。由程序自动写入，手工改也行 |
| `manualHeight` | 整数 | 180–1400（**0 = 未设置**） | 上次手动拖拽调整后的窗口高度。`0` 表示从未调整过，此时使用默认 720。运行时仍会与工作区高度取小值 |

> **窗口位置不会被保存**，每次启动都回到主屏右侧默认位置。这是刻意设计——避免同学拖到奇怪的位置后下次启动找不到窗口。
> 但**窗口大小会被保存**（`manualWidth`/`manualHeight`）：大小是阅读偏好（老师可能喜欢更宽以一行多放几个科目），
> 每次都重置会让人反复拖动。想恢复默认大小，把这两个值改成 `0` 即可。

> **`order` 会被卡片排序功能自动重编**：点卡片上的 `▲`/`▼` 调整顺序后，程序会把全部可见科目的 `order`
> 重新写成 `10, 20, 30 …`（步长 10）。这是有意为之——比保留零散数字更易读，
> 也留出了手工插入的空间（想插到第 1 和第 2 之间，写 `15` 即可）。

#### subjects 数组（科目）

| 字段 | 类型 | 含义 |
|---|---|---|
| `key` | 字符串 | 科目键名，**必须唯一**，也是 `homework.json` 里的键。建议只用小写字母 |
| `name` | 字符串 | 显示在卡片标题上的名字 |
| `color` | 字符串 | 主题色，必须是 `#RRGGBB` 六位十六进制格式 |
| `enabled` | 布尔 | `false` 时该科目不显示（数据不丢失，改回 `true` 即可恢复） |
| `order` | 整数 | 排序，数字小的排前面 |

**默认内置 10 个科目**：语文、数学、英语、物理、化学、道德与法治、历史、地理、生物、其他。

> 需求里的"小四门"已按默认假设拆分为 **道德与法治 / 历史 / 地理 / 生物** 四个独立科目。
> 如果需要合并成一科显示，把要隐藏的科目 `enabled` 改成 `false`，然后在剩下的科目里填内容即可。

**新增一个科目**：在 `subjects` 数组末尾加一个对象（**注意前一个对象后面要加逗号**）：

```json
,
{ "key": "pe", "name": "体育", "color": "#FFD60A", "enabled": true, "order": 100 }
```

保存后点悬浮窗的 `↻` 即可看到新科目。

#### templates 数组（作业模板）

| 字段 | 类型 | 含义 |
|---|---|---|
| `label` | 字符串 | 编辑对话框里显示的胶囊按钮文字 |
| `prefix` | 字符串 | 前缀，点模板后自动填入 |
| `suffix` | 字符串 | 后缀，光标会停在前缀和后缀中间 |
| `enabled` | 布尔 | `false` 时不显示这个模板 |

**工作原理**：点"练习册"胶囊 → 输入框填入 `练习册第  页` → 光标停在中间 → 直接按数字键就成了 `练习册第 12 页`。

**新增模板**示例：

```json
,
{ "label": "默写", "prefix": "默写 ", "suffix": " 遍", "enabled": true }
```

### 3.2 homework.json

```json
{
  "version": 1,
  "_说明": "dates -> 日期(yyyy-MM-dd) -> 科目键名 -> 作业条目数组",
  "dates": {
    "2026-09-18": {
      "chinese": [
        {
          "id": "a1b2c3d4e5f6",
          "content": "练习册第 12 页 1-8 题",
          "done": false,
          "createdAt": "2026-09-18 20:30:00"
        }
      ],
      "math": [
        { "id": "f6e5d4c3b2a1", "content": "书第 45 页", "done": true, "createdAt": "2026-09-18 20:31:00" }
      ]
    }
  }
}
```

| 层级 | 说明 |
|---|---|
| `dates` | 顶层容器，按日期分组 |
| `"2026-09-18"` | 日期键，**必须是 `yyyy-MM-dd` 格式**（月日补零）。格式不对的键程序会忽略 |
| `"chinese"` | 科目键名，**必须与 settings.json 里 subjects 的 key 一致** |
| 数组元素 | 一条作业 |

**条目字段**

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | 字符串 | 唯一标识，用于精确定位。**删除或改成重复值可能导致编辑/删除错条目**，建议不动 |
| `content` | 字符串 | 作业内容，可以包含中文、空格、标点 |
| `done` | 布尔 | 是否已完成。`true` 时界面显示删除线 |
| `createdAt` | 字符串 | 创建时间，仅作记录，可留空 |

> **空科目会自动清理**：某科目当天最后一条作业被删除后，对应的键会被自动移除，保持 JSON 干净。

## 四、用记事本手工修改与修复

### 4.1 手工添加作业

1. 右键 `homework.json` → 打开方式 → 记事本。
2. 找到今天的日期键（如 `"2026-09-18"`）。
3. 找到对应科目（如 `"math"`），在数组里照抄一行：

```json
{ "id": "", "content": "预习第 3 章", "done": false, "createdAt": "" }
```

4. **注意**：如果数组里已有内容，新行前面要有英文逗号 `,`；`id` 留空程序会自动补。
5. 保存，回到悬浮窗点 `↻`。

### 4.2 手工修复损坏的 JSON

**症状**：悬浮窗状态栏提示"settings.json JSON 格式错误，已备份为 xxx.corrupt_时间戳.json，并重建默认内容"。

**这意味着**：你的原文件已经被改名备份，程序用默认内容重新生成了一个。你的内容没有丢，但改错了。

**修复步骤**：

1. 在程序目录找到 `settings.json.corrupt_20260918_203000.json`（或 `homework.json.corrupt_...`）。
2. 用记事本打开它，**不要用 Word**（Word 会插入智能引号）。
3. 逐条检查下面 5 个最常见的语法错误：

| 错误类型 | 错误示例 | 正确写法 |
|---|---|---|
| 中文引号 | `"name"： "语文"` | `"name": "语文"`（半角引号 + 半角冒号） |
| 多余的逗号 | `{ "a": 1, }` | `{ "a": 1 }`（最后一个元素后不能有逗号） |
| 漏掉逗号 | `{ "a": 1 "b": 2 }` | `{ "a": 1, "b": 2 }` |
| 括号不配对 | 少一个 `}` 或 `]` | 数一遍开闭括号数量是否相等 |
| 用了全角逗号 | `"a"："1"，` | 所有分隔符必须是英文半角 `,` |

4. 修好后，把内容**整体复制**回 `settings.json`（覆盖程序生成的默认内容）。
5. 点悬浮窗的 `↻` 验证。

**更省事的办法**：如果你改的内容不多，直接放弃那个 `.corrupt` 文件，在程序生成的默认 `settings.json` 上重新改一次。

**小技巧**：把 JSON 内容粘到 https://jsonlint.com 或 Windows 上的 VS Code 里，它会直接告诉你第几行错了。

### 4.3 恢复到出厂状态

删除 `settings.json` 和 `homework.json`（**注意备份**），重启程序，会自动生成全新的默认配置。

只想重置设置、保留作业：删掉 `settings.json` 一个文件即可。

## 五、常见错误与处理

| 现象 | 原因 | 处理方法 |
|---|---|---|
| 双击没反应，窗口不出现 | 程序已在运行 | 检查任务栏，第一个实例的窗口会自己跳出来 |
| 状态栏显示"当前目录不可写" | 程序放在 `C:\Program Files` 等受保护目录 | 把整个文件夹移动到桌面或 D 盘 |
| 状态栏显示"JSON 格式错误，已备份…" | 手工编辑时写错了语法 | 见 4.2 节；程序不会崩溃，用的是默认配置 |
| 修改后重启又变回去了 | 目录不可写，修改只在内存中 | 换到可写目录运行 |
| 窗口跑到屏幕外面了 | 显示器数量或分辨率变了 | 程序会自动拉回可见范围；还不行就删掉 `settings.json` 重启 |
| 字太小/太大看不清 | 字号设置不合适 | 点 `⚙` 调"作业文字大小"，或改 `settings.json` 的 `fontSize` |
| 想一行放更多科目 | 卡片太宽或窗口太窄 | ① 点 `⚙` 把"卡片宽度"调小到 240–280；② 拖窗口边缘把窗口拉宽 |
| 关闭后提示文件被占用 | 记事本或杀毒软件锁住了 JSON | 关掉记事本；杀毒软件把程序目录加白名单 |
| 多人同时开导致数据冲突 | 多开 | 程序已内置单实例限制；如果确实需要多开，请指定不同的程序目录 |
| 窗口太高、压住了任务栏 | `maxHeight` 设太大 | 点 `⚙` 调「窗口最大高度」（建议 600–750），或改 `settings.json` 的 `maxHeight`。程序本身也会自动不超过屏幕工作区高度，若仍异常请检查显示缩放设置 |
| 空科目卡片占地方太多 | 正常（常驻显示） | 空卡片已折叠（约为有作业卡片的一半高）。若还是不想要，把该科目 `enabled` 改成 `false` 即可彻底隐藏 |
| 点 `▲`/`▼` 不换位 | 已经在最前/最后 | 状态栏会提示"已经在最前面了/最后面了"。按钮本身不作禁用态，属正常行为 |
| 窗口边缘拖不动大小 | 没对准 8 像素的热区 | 光标变成双箭头时再按下；四边 8px、四角 14×14。**注意右边缘中间约 1/4 区域是留给滚动条的，不响应缩放**，拖那里请改用上方或下方的右边缘 |
| 窗口大小每次都要重调 | `manualWidth`/`manualHeight` 为 0 或目录不可写 | 拖边缘调整后会自动记住（600ms 后落盘）；若目录不可写则无法保存，请换到可写目录 |
| 右下角三条斜线拖了没反应 | 那只是视觉提示，不是控件 | 缩放靠拖**窗口边缘**。三条斜线已设事件穿透，拖它等于拖右下角热区，正常表现是光标在角上变斜箭头 |

### 6.4 关于体积和性能的取舍说明

发布参数（见 `HomeworkBoard.csproj`）做了这些选择：

| 参数 | 值 | 原因 |
|---|---|---|
| `PublishSingleFile` | `true` | 打成单文件，双击即用 |

2. **保持自包含**：60 MB 在 U 盘/局域网内复制毫无压力，且绝对不会有"缺少运行库"的问题。**推荐维持现状**。

### 6.5 验证是否真的不需要运行库

在一台**没装过 .NET** 的 Windows 10 上直接双击 exe。如果能正常弹出窗口，说明自包含打包成功。

## 七、技术设计说明

### 7.1 为什么选 WPF 自包含单文件

- WinForms 做不出圆角半透明 + 现代暗色 UI 的观感；
- C++ Win32 体积小但开发成本高，且改字号/换肤代价大；
- WPF 自包含单文件 60 MB 换来的是"绝对开箱即用"——这是需求的第一优先级。

### 7.2 性能目标如何达成

| 目标 | 实现方式 |
|---|---|
| 冷启动 < 2 秒 | 不做磁盘遍历、不联网、不加载图片资源；只读两个几 KB 的 JSON；界面本身极简 |
| 空闲内存 < 50 MB | 单一窗口，UI 元素数量与作业条目数成正比而非常数；无缓存、无后台线程池滥用 |
| 空闲 CPU ≈ 0% | **唯一常驻定时器是 60 秒一次的跨天检测**，回调内只做一次 `DateTime.Today` 比较 |
| 无动画 | 完全不用 `Storyboard`、不用 `Opacity` 动画、不用 `DropShadowEffect` 的动态变化 |

> 静态投影（`DropShadowEffect`）保留了一个——它在渲染时只算一次，不是持续性开销，但视觉层次感提升明显。

### 7.3 横向网格自适应换行算法

需求（第 8 轮修订）："卡片顺序是横着堆不下了再竖着"——
即**先横向铺满一行，一行放不下再换到下一行**。
（早期版本是"纵向填满一列，放不下往左另起一列"，已废弃。）

实现（`MainViewModel.RefreshLayout`）：

1. 遍历**全部启用科目**（含无作业的，它们常驻显示但视觉淡化）；
2. 按 `order` 顺序逐个卡片追加到当前行，累加已占宽度；
3. 当前行已有内容且**再放一张就超出可用宽度** → 另起一行，继续装；
4. 结果暴露为 `Rows` 集合，界面用两层 `ItemsControl` 渲染：
   外层 `StackPanel Orientation="Vertical"`（行），内层 `StackPanel Orientation="Horizontal"`（卡片）。

可用宽度 = **窗口当前实际宽度** − 内容区左右内边距（10+10）− 滚动条预留（14）。
刻意取"当前宽度"而非配置值：窗口现在可以手动缩放，缩窄后必须重新分行，
因此 `MainWindow.SizeChanged` 会把实测宽度经 `SetLayoutWidth` 回传给视图模型。

> `SetLayoutWidth` 内有 20 像素阈值过滤——拖动缩放时 `SizeChanged` 高频触发，
> 每帧重算布局是纯粹的浪费（性能目标要求空闲 CPU ≈ 0%），而小于 20 像素的变化不可能改变"一行放几张"。

宽度换算要点：卡片自身宽 = `columnWidth`，卡片右间距 10（`Margin="0,0,10,10"`），
因此槽宽 = `CardWidth + 10`（`CardSlotWidth`）。
这与旧版多列布局的关键差别：旧版间距挂在外层列容器上，卡片自身无左右 Margin；
改成横向网格后间距移到卡片上，**必须在槽宽里补回来**，否则会多算一张卡片导致最后一张被裁掉。

**空科目「折叠」处理**：无作业的卡片会
① 整块收起条目列表（`ItemsControl` 的 `MinHeight=26` 与 `Margin=0,6,0,0` 会撑出空白，
   这正是"科目名和暂无作业之间空隙很大"的根因）；
② 收紧内边距（`12,10,10,12` → `12,3,10,4`）；
③ 卡片下间距减半（`10` → `6`）；
④ 占位文字 `Margin` 压到 `0,1,0,0`，字号取正文字号的 80%（上限 24）并显式设行高。
效果：空卡片高度约 **79 逻辑像素**（折叠前约 106），有作业两条的卡片约 168 ——
空卡片明显矮一截，且卡片会随作业增删在折叠/展开间切换，视觉上一眼能看出哪些科目有作业。

**关于"空科目常驻"的设计变更**：原始需求写"没有作业的学科不显示对应窗口"，
但实测发现两个问题——全部无作业时界面空白找不到入口；科目位置随作业增删浮动，
大屏上学生难形成固定认知。因此改为空科目淡化常驻（详见 1.5 节说明）。
若确实要隐藏某科目，把 `settings.json` 里该科目的 `enabled` 设为 `false`。

### 7.3.1 卡片排序：每张卡片左侧的 ▲ / ▼ 按钮（第 8 轮新增，第 2 版）

需求："可调整卡片顺序"。

第 1 版实现的是**长按 0.5 秒后拖拽**，实机上失效。根因：

- 卡片位于 `ScrollViewer` 内，其 `PanningMode="VerticalOnly"` 会抢先消费触摸事件
  （`ScrollViewer` 把 `TouchDown` 拿去做滚动），卡片的手势往往收不到，或收到后立刻被
  `TouchLeave` 取消；
- 鼠标路径虽能触发，但用户反馈"无法调整"。

第 2 版按用户指定改为**按钮方案**：每张卡片标题行最左侧竖排 `▲` / `▼` 两个按钮。

| 操作 | 行为 |
|---|---|
| 点 `▲` | 本卡片在排序中**往前移一位** |
| 点 `▼` | 本卡片在排序中**往后移一位** |
| 已在首位再点 `▲` | 不换位，状态栏提示"「科目名」已经在最前面了" |
| 已在末位再点 `▼` | 不换位，状态栏提示"「科目名」已经在最后面了" |

实现要点：

- 按钮 `Tag="{Binding}"` 直接挂当前 `SubjectCardViewModel`，`Click` 里取 `Tag` 即可定位；
- 两个按钮共用 `MoveCardByButton(sender, direction)`，只有方向参数不同；
- 按钮尺寸 26×22，两枚纵向叠放。**有意小于常规 34px 触屏标准**：
  卡片本身密集，且排序是低频操作、误触代价低（再点回来即可）；
- 事件处理里没有任何手势识别逻辑——触屏与鼠标行为完全一致，这是方案的核心优势；
- `MoveCard` 的做法：先在内存列表重排 → 按新顺序把 `Order` 重编为 `10,20,30…` →
  同步 `_settings.Subjects` 列表顺序 → 重建卡片 + 重算布局 + 触发节流保存。
  `Order` 重编为紧凑序列，手工编辑 JSON 时好认，也便于再插入；
- 边界不做按钮禁用态（避免多一次绑定与计算），改为**点击时状态栏提示**，
  让"点不动"这件事有明确反馈，不会被误解为程序卡死；
- 被禁用的科目不在可见排序里，重排时其 `order` 顺延到可见科目之后（保持相对顺序），
  重新启用时会排在末尾，用户可再次调整。

### 7.3.2 窗口尺寸调整（第 8 轮新增，第 3 版 —— 设置面板实时调整）

需求："可直接触屏/鼠标调整窗口大小（有最小限定）"。

#### 为什么前三版都失败

| 版本 | 做法 | 结果 |
|---|---|---|
| 第 1 版 | 靠 `ResizeMode="CanResize"` 让系统提供边框热区 | 完全抓不到，热区不存在 |
| 第 2 版 | 自绘握把，拖动时直接改 `Width`/`Height` | 改不动，尤其**宽度完全无反应** |
| 第 3 版 | `WindowChrome.ResizeBorderThickness="6"` | 同样无效，且该属性与 `AllowsTransparency` 有已知冲突 |
| 第 3 版附 | 自绘 8 个透明热区 + 发送 `WM_SYSCOMMAND` + `SC_SIZE` | **实机仍不可靠** |
| **第 4 版（当前）** | **设置面板滑块 + `WindowSizeRequested` 事件实时应用** | **确定可用** |

根本原因（关键认知）：

> `WindowStyle="None"` + `AllowsTransparency="True"` 在 Win32 层面创建的是
> **分层窗口（`WS_EX_LAYERED`）**。分层窗口**没有非客户区（NC area）**，
> 因此系统原生的 8 个边框缩放热区**全部不存在**。
> `ResizeMode` 只是"允许被改尺寸"的标志位，没有热区就没人能拖；
> `WindowChrome.ResizeBorderThickness` 也只在有 NC 区时才被系统采用，同样落空。
>
> **重要修正**：早先认为"程序内赋值 `Width` 会被分层窗口吞掉"是误判。
> 实测（`_verify/ui` 断言）**程序内赋值 `Width`/`Height` 完全有效**，
> 真正失败的是**鼠标/触摸的命中测试链路**——分层窗口下自绘热区收不到可靠的按压事件。
> 因此结论是：**不要在外围做交互热区，改从设置面板驱动尺寸。**

#### 第 4 版实现

设置面板新增「窗口宽度」「窗口高度」两个滑块，拖动即实时改变悬浮窗尺寸。

| 环节 | 做法 |
|---|---|
| 滑块 | `WinWidthSlider`（280—屏幕可用宽度）、`WinHeightSlider`（180—`MaxWindowHeight`），`TickFrequency=20` |
| 视图模型 | `MainViewModel.RequestWindowSize(width, height)` —— 传 `0` 表示"该维度不变" |
| 夹紧 | `ClampWindowSize(...)`：下限 `MinWidth/MinHeight`，宽度不超过「工作区宽 − 2×EdgeMargin」，高度不超过 `MaxWindowHeight` |
| 通知宿主 | `WindowSizeRequested` 事件（`WindowSizeEventArgs`）；**视图模型不持有 `Window` 引用**，保持可测试性 |
| 宿主响应 | `MainWindow.OnWindowSizeRequested` 赋 `Width`/`Height` + `SyncLayoutWidth()` 立即重算分行 |
| 持久化 | 夹紧后的值经 `SetManualWindowSize` 写入 `manualWidth`/`manualHeight`，走 800ms 节流保存 |
| 上限联动 | 调「窗口最大高度」时同步调整高度滑块上限；若当前高度超限则一并拉回并应用 |

设计要点：

- **顺序敏感**：必须先设 `Slider.Minimum`/`Maximum` 再设 `Value`。
  WPF 在 `Maximum` 变小时会立刻把超出的 `Value` 夹到新上限，
  顺序反了会丢掉用户原来的尺寸值；
- 手动给 `Slider.Value` 赋值**不会**自动吸附刻度，因此用 `SnapToTick()` 自己算，
  避免显示 `381 px` 这类零碎值；
- 宽度传 `0`、高度传实际值（反之亦然），这样拖一个滑块不会把另一维度重置成默认值；
- 提高最大高度上限**不会**主动把窗口拉高——上限只做约束不做驱动。
  否则用户把上限调回 720 时窗口会莫名变大，属于意外行为。
  （这一条已写成 `_verify/ui` 的断言。）

`SizeToContent` 从 `WidthAndHeight` 改为 `Manual` 是必须的：
只要 `SizeToContent ≠ Manual`，窗口尺寸就由内容驱动，尺寸变更会被内容重新算回去，
表现为"怎么设都没反应"。改为 `Manual` 后必须给 `Width`/`Height` 赋初值，
否则窗口会塌成 0×0。

`manualWidth`/`manualHeight` 的 `0` 是"从未手动调整过"的哨兵值——
`NormalizeSettings` 里对这个值做特判，不参与夹紧，否则会被夹到下限 `280`，
导致默认宽度 `380` 永远失效。

> **不要加 `WindowChrome`**。它与 `AllowsTransparency="True"` 组合有已知冲突
> （可能启动白屏或窗体向外扩），且对分层窗口并不产生有效的缩放热区。

右下角状态栏的三条斜线图标（`ResizeGrip`）保留为视觉提示（`IsHitTestVisible="False"`），
但**不再承担交互功能**——调尺寸请用设置面板的滑块。

### 7.3.3 标题栏高度（第 8 轮第 2 版修复）

用户反馈："**今日作业 · 按住空白处可拖动本窗口** 的部分变体栏过高"。

实测标题栏高度 **197.6 px**，而栏内两个子元素加起来只有 36.8 px。

根因不在标题栏自身，而在**缩放热区**：

> `RootLayout` 是 4 行 Grid（标题栏 `Auto` / 工具条 `Auto` / 内容 `*` / 状态栏 `Auto`）。
> 自绘的 8 个缩放热区加入时**没有设 `Grid.Row` 与 `Grid.RowSpan`**，
> 于是全部默认落在 **Row 0 且只占 1 行**，参与并主导了 Row 0 的 `Auto` 高度计算，
> 把标题栏撑到 186 px（Grid 高度）→ 加上 Padding 成为 197.6 px。

修复：`CreateHotspotBorder` 里显式 `Grid.SetRow(hotspot, 0)` + `Grid.SetRowSpan(hotspot, 4)`，
让热区跨满所有行，只作为最上层覆盖物存在，不再影响任何行的高度。
修复后标题栏 **48 px**（`_verify/ui` 有断言守卫，阈值 ≤ 52）。

同时收紧了两处样式（次要因素）：

| 位置 | 原值 | 现值 |
|---|---|---|
| `TitleBar` Padding | `14,10,10,8` | `14,6,10,5` |
| 左侧信息块对齐 | `VerticalAlignment="Center"`（但右侧按钮栈是 `Top`） | 左右**都** `Center` |
| 拖动提示行高 | 未设（随字号浮动） | `LineHeight="13"` |

> **教训**：往一个带行定义的 `Grid` 里动态添加覆盖物时，**必须显式设 `Row`/`RowSpan`**，
> 否则它会落进 Row 0 并破坏 Auto 行的尺寸。这类问题肉眼看不出来，
> 只能靠实测 `ActualHeight` 定位——所以 `_verify/ui` 里加了标题栏高度的回归断言。

### 7.4 容错设计

| 异常场景 | 处理 |
|---|---|
| JSON 文件不存在 | 自动创建默认文件 |
| JSON 语法错误 | 备份为 `xxx.corrupt_时间戳.json` → 重建默认 → 状态栏温和提示 |
| JSON 是空文件 | 同上，视为损坏 |
| 字段缺失 | 逐字段补默认值（`NormalizeSettings` / `NormalizeHomework`） |
| 字段类型错误 | `JsonSerializer` 容错选项处理；数值越界自动夹紧 |
| 颜色格式非法 | 回退到灰色 `#8E8E93` |
| 目录不可写 | 进入内存模式，功能照常，状态栏提示换目录 |
| 保存时文件被占用 | 静默失败 + 状态栏提示，**不崩溃、不丢内存数据** |
| 窗口拖出屏幕 | `ClampIntoWorkArea` 保证标题栏始终可点 |
| 窗口被拖大后超出屏幕 | 松手时 `ClampIntoWorkArea` 把右/下边缘拉回工作区 |
| 换到小屏后窗口过高 | `MaxHeight` 绑定 `MaxWindowHeight`，运行时与工作区高度取小值 |
| 高 DPI 屏上启动高度算错 | `ContentRendered` 里 `ReapplyHeightLimit` 用真实 DPI 再夹一次 |
| 显示器被拔掉 / 分辨率变小 | `EnsureVisible` 自动拉回可见区域 |
| 任意未捕获异常 | 全局 `DispatcherUnhandledException` 兜底，提示后继续运行 |
| 多开 | 命名互斥体限制单实例，第二个实例激活第一个后自动退出 |

### 7.5 原子写入

保存时不用 `File.WriteAllText` 直接覆盖，而是：

1. 写入临时文件 `xxx.<随机串>.tmp`（UTF-8 无 BOM）
2. 用 `File.Replace` 原子替换目标文件（首次写入时用 `File.Move`）

这样任何时刻磁盘上要么是完整的旧文件、要么是完整的新文件，**不会出现"写了一半断电"导致的半截 JSON**。

### 7.6 节流保存

`ThrottledSaver` 在数据变化后**等 800ms** 才真正写盘。连续勾选 10 条作业只会写 1 次磁盘。

程序关闭时强制 `FlushNow()`，保证最后几秒的修改不丢失。

### 7.7 DPI 与多显示器

- `app.manifest` 声明 `PerMonitorV2`，窗口在不同缩放的显示器间拖动时自动重新适配，**不模糊**；
- 屏幕坐标计算全程区分**物理像素**（Win32 返回）与**逻辑像素**（WPF 的 `Left`/`Top`），用当前显示器的 DPI 比例换算——这是多屏不同缩放下窗口不跑到屏幕外的关键。

## 九、已知限制

1. **只有"今天"能被编辑**。界面显示的是当天日期，跨天后自动切换。如果想提前录入明天的作业，可以直接编辑 `homework.json`（把日期键写成明天的日期）。
2. **科目增删需要手工改 JSON**。设置窗口里只能勾选启用/隐藏，新增科目要编辑 `settings.json` 的 `subjects` 数组。
3. **不支持作业条目的排序**。卡片（科目）可以用 `▲`/`▼` 按钮调整顺序，但卡片内部的作业条目仍按添加顺序显示。要调整顺序只能删掉重建，或手工编辑 `homework.json` 里对应数组的元素次序。
4. **不支持导出**。数据就是 JSON 文件本身，需要的话直接复制走。
5. **多屏不同缩放时**首次定位依赖 Win32 的 `MonitorFromPoint`，在极少数虚拟显示驱动下可能有几像素偏差——程序有二次纠偏，不影响使用。
6. **窗口右边缘中间有一段不能缩放**。内容区的垂直滚动条贴在窗口右缘，为避免抢走滚动条的拖动，右边缘中间约 24% 的高度未设缩放热区。要横向拉宽请用左边缘，或拖右边缘的上/下段、右上角、右下角。
